Hayulo Project Tutorial

Learn Rust by Building a Programming Language Toolchain

This tutorial assumes you are new to Rust. It uses this repository as the textbook: a small language with a lexer, parser, static checker, interpreter, formatter, project system, JSON diagnostics, benchmark reader, and REST API generator.

Audience Rust beginner, language-tooling beginner, comfortable with command lines.
Goal Understand how Rust code maps to compiler and interpreter concepts.
Project Use cargo run -- ... and inspect the Rust modules under src/.

1. Run the Project First

Before reading Rust, run the toolchain. A language project makes much more sense when you can see its inputs and outputs. 

rustup toolchain install stable
cargo run -- --version
cargo run -- run examples/hello.hayulo
cargo run -- test examples/data_core.hayulo
cargo run -- check examples/todo_api/main.hayulo --json
cargo run -- build examples/todo_api/main.hayulo

The command format is important: cargo run -- means "run the Rust binary, and pass everything after -- to the binary itself."

Practical habit: after each code change, run cargo check first. It is faster than a full test run and catches most Rust mistakes immediately.

2. Rust Basics You Need for This Codebase

You do not need to know all of Rust to work on Hayulo. Start with the concepts that show up repeatedly in this repository.

Cargo is the project manager

Cargo.toml declares the package, binary, and dependencies: clap for CLI parsing, regex for text patterns, serde and serde_json for JSON, and walkdir for recursive file discovery. 

[package]
name = "hayulo-lang"
edition = "2024"

[[bin]]
name = "hayulo"
path = "src/main.rs"

Modules are files

src/lib.rs exposes modules. For example, pub mod lexer; means Rust should compile src/lexer.rs and make it visible to other modules. 

pub mod lexer;
pub mod parser;
pub mod checker;
pub mod interpreter;

Result is Rust's normal error path

Hayulo uses HayuloResult<T>, which is an alias for Result<T, HayuloError>. A function returning this type either returns Ok(value) or Err(error). 

pub type HayuloResult<T> = Result<T, HayuloError>;

pub fn lex(source: &str, filename: Option<&str>) -> HayuloResult<Vec<Token>> {
    Lexer::new(source, filename).lex()
}

The question mark operator propagates errors

In Rust, ? means: if this is Ok, unwrap the value; if it is Err, return that error from the current function. 

let tokens = lex(source, Some(filename))?;
let program = parse(tokens, Some(filename))?;
check_program(&program, Some(filename))?;

Enums model language syntax

A programming language has many possible statements and expressions. Rust enums are a natural fit because each variant can carry different data. 

pub enum Stmt {
    Let { name: String, expr: Expr, line: usize },
    Return { expr: Expr, line: usize },
    If { condition: Expr, then_body: Vec<Stmt>, else_body: Vec<Stmt> },
}

Borrowing is how Rust avoids accidental mutation

&T means a read-only borrow. &mut T means a mutable borrow. Most compiler passes borrow the AST instead of copying it. 

pub fn check_program(program: &Program, filename: Option<&str>) -> HayuloResult<()> {
    StaticChecker::new(program, filename).check()
}
Rust words you will see often
TermMeaning in this project
structA named bundle of fields, such as Token or Diagnostic.
enumA value with several possible shapes, such as Expr or Stmt.
implMethods attached to a type, such as Parser::parse.
Option<T>Either Some(value) or None.

3. The Compiler and Toolchain Mental Model

Hayulo is not only an interpreter. It is a toolchain. The CLI chooses a workflow, then routes source code through several passes.

Source .hayulo text written by a human or coding agent.
Lexer Turns characters into tokens.
Parser Turns tokens into an AST.
Checker Finds name, type, arity, and return errors.
Runtime Interprets scripts and runs tests.
Generator Builds REST API files for API sources.

A compiler pass should usually do one job. For example, the lexer should not decide whether a function return type is correct. The checker should not parse raw strings. Keeping those responsibilities separate makes the project easier to change.

5. Lexer: Turning Text into Tokens

The lexer reads characters and emits tokens. A token has a kind, value, line, and column. The parser does not want to care about raw characters. 

pub struct Token {
    pub kind: String,
    pub value: String,
    pub line: usize,
    pub column: usize,
}

Example input: 

fn main() {
  print("Hello")
}

Conceptually becomes: 

FN IDENT("main") LPAREN RPAREN LBRACE IDENT("print") LPAREN STRING("Hello") RPAREN RBRACE EOF
Language design rule: good token locations matter. Diagnostics for coding agents are only useful when they point at the right line and column.

How to add a keyword

  1. Add the keyword to the keyword match in src/lexer.rs.
  2. Decide where the parser should accept that token.
  3. Add a diagnostic for the most common wrong usage.
  4. Add a fixture or CLI test that exercises the keyword.

6. Parser and AST: Turning Tokens into Meaning

Hayulo uses a recursive descent parser. That means grammar rules are implemented as Rust methods. For example, expression parsing is split into precedence levels: or, and, equality, comparison, term, factor, unary, call, primary. 

fn expression(&mut self) -> HayuloResult<Expr> {
    self.or()
}

The AST is the central data structure. Once the source becomes AST, the checker and interpreter no longer need to know about punctuation.

SyntaxAST shapeLater consumer
let x = 1Stmt::LetChecker binds a name. Interpreter stores a value.
x + yExpr::BinaryChecker verifies operand types. Interpreter computes.
Some(value)Expr::VariantLiteralChecker tracks Option. Interpreter creates runtime value.
match result { ... }Stmt::MatchChecker enforces exhaustiveness. Interpreter selects a case.
Why the parser should not execute code

Parsing is about structure, not behavior. If the parser starts evaluating expressions, it becomes harder to produce clear diagnostics, harder to test, and harder to support tools like formatters and language servers.

7. Diagnostics: The Product Surface for Coding Agents

Hayulo treats errors as structured data. The CLI can print prose for humans, or JSON for repair loops. The same Diagnostic type supports both. 

Diagnostic::new("file_not_found", "Hayulo source file not found.")
    .file(Some(path))
    .suggestion("Check the path and try again.")

A good diagnostic has four parts:

  1. Stable code: machine-readable, such as syntax.postfix_try_removed.
  2. Plain message: explains the problem in human language.
  3. Location: file, line, and column when possible.
  4. Suggestion: tells the user or agent what to try next.
{
  "schema": "hayulo.diagnostics@0.1",
  "status": "failed",
  "diagnostics": [
    {
      "code": "syntax.binding_requires_let_or_set",
      "severity": "error",
      "message": "Hayulo 2.0 uses explicit let/set binding syntax."
    }
  ]
}

8. Static Checker: Catch Mistakes Before Running

The checker walks the AST and infers simple static types. It tracks names in environments, validates function arity, checks return types, and makes sure match statements handle required variants. 

struct StaticType {
    name: String,
    item: Option<Box<StaticType>>,
    key: Option<Box<StaticType>>,
    value: Option<Box<StaticType>>,
    fields: Option<BTreeMap<String, StaticType>>,
}

This is a classic compiler pass:

  1. Collect function signatures.
  2. Check function bodies.
  3. Check tests.
  4. Return the first structured error.

The checker is intentionally conservative. A small language is easier for agents to generate and repair than a large language with many implicit rules.

9. Interpreter: Executing Hayulo Scripts

The interpreter has a runtime Value enum. Static types describe what should happen; runtime values are what actually happen. 

pub enum Value {
    None,
    Bool(bool),
    Int(i64),
    Float(f64),
    Text(String),
    List(Vec<Value>),
    Record { type_name: String, fields: BTreeMap<String, Value> },
}

Function calls create an environment. let stores values in the current environment. set searches existing environments and updates a binding.

Runtime conceptWhere it appearsWhy it matters
Environment stackenv_stackFunction calls and match bindings need scopes.
Return controlControl::ReturnA return must stop the current block immediately.
Built-insprint, lenSmall standard behavior without a full standard library.
Runtime errorsruntime_errorErrors stay structured instead of becoming crashes.

10. API Generator: A Different Language Track

Hayulo has two tracks. Script files go through the lexer, parser, checker, and interpreter. API-style files are parsed by src/api.rs into ApiSpec, then validated and generated into Node.js files. 

module todo_api

app TodoApi {
  type Todo = record {
    id: Id<Todo>
    title: Text { min: 1, max: 200 }
  }

  route GET "/todos" -> List<Todo> {
    effect api.read
    effect storage.local
    action list Todo
  }
}

The generator writes:

  • hayulo.ir.json: intermediate representation for tools.
  • openapi.json: OpenAPI 3.1 document.
  • server.mjs: dependency-free Node server.
  • smoke_test.mjs: generated integration test.
  • package.json and README.md: runtime instructions.
Design insight: API generation is easier because Hayulo restricts route bodies to declarations like effect and action. Less freedom means better diagnostics and more predictable generated code.

11. Guided Exercises

These exercises are ordered from safe reading tasks to real language changes.

Beginner

Exercise 1: Trace hayulo run examples/hello.hayulo

  1. Open src/main.rs.
  2. Follow the call into src/cli.rs.
  3. Find the Run command handler.
  4. Trace how it loads, parses, checks, and interprets the file.
cargo run -- run examples/hello.hayulo
Beginner

Exercise 2: Add a Better Diagnostic Suggestion

Find a diagnostic in src/parser.rs or src/checker.rs. Improve the suggestion text without changing behavior. 

cargo check
cargo run -- check tests/fixtures/syntax_error.hayulo --json
Intermediate

Exercise 3: Add a Built-in Function

Add uppercase(text). You need to update both the checker and the interpreter.

  1. In src/checker.rs, teach infer_call that uppercase accepts one Text and returns Text.
  2. In src/interpreter.rs, teach call_function to return an uppercase string.
  3. Add an example or fixture that calls uppercase("hayulo").
Intermediate

Exercise 4: Add a New Operator

Add support for a simple exponent operator only if you first decide its token, precedence, type rules, and runtime behavior.

QuestionExample answer
TokenDOUBLE_STAR for **
Parser precedenceBetween unary and factor, or inside factor.
Checker ruleNumbers only. Return Float or Int.
Runtime ruleUse Rust numeric operations carefully.
Advanced

Exercise 5: Add a Small Syntax Feature

Add while loops. This touches the full language pipeline.

  1. Lexer: add while as a keyword.
  2. AST: add Stmt::While.
  3. Parser: parse while condition { ... }.
  4. Checker: require a valid condition expression and check the body.
  5. Interpreter: execute until the condition is false.
  6. Diagnostics: handle malformed syntax clearly.
